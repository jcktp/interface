### State Management

Global store is at `src/store/index.ts` using Zustand. It holds:
- `user`, `token`, `isAuthenticated` — auth state
- `employees`, `candidates` — local employee data (for sample/uploaded data)
- `dataUploads`, `apiConnections` — integration state
- `currentFilter` — global filter state shared across all pages

### Routing

All app routes live under `/app/*` in `src/App.tsx`. Protected routes use `PermissionGuard` which checks `user.permissions` array.

Key routes:
- `/app/dashboard` — main analytics dashboard
- `/app/command-center` — real-time health dashboard
- `/app/ml-models` — prediction modeling
- `/app/query-editor` — SQL editor
- `/app/metrics` — metric definitions
- `/app/data` — data & integrations (merged from DataManagement + ApiConnections)

## Authentication

- **Mechanism**: Server-side token store (Redis or in-memory dict)
- **Token format**: Opaque string (not JWT), generated by `security.py`
- **Login flow**: `POST /api/auth/login` → validates credentials → stores token → returns `{token, user, permissions}`
- **Request auth**: `Authorization: Bearer <token>` header → `verify_token` dependency validates against store
- **Permissions**: `user.permissions` array checked by `PermissionGuard` in frontend

## Permission System (RBAC)

Roles: `super_admin`, `hr_manager`, `recruiter`, `analyst`, `finance`, `manager`, `viewer`

Each role maps to a set of `Permission` enum values (defined in `services/permissions.py`).

Users can have `custom_permissions: JSON` column that overrides their role-based permissions when set.

## ML Architecture

The ML layer uses a **simulation-based** approach for in-container training:
- `MLService._simulate_training()` uses real employee data to derive deterministic training metrics
- No model serialization (no joblib/pickle files) — metrics are stored as JSON in `ml_models.metrics`
- Predictions are computed on-the-fly using `_calculate_attrition_risk_score()` which weights real employee attributes
- Headcount forecasts use simple linear projection with seasonality

ML libraries available: `scikit-learn`, `xgboost`, `lightgbm`, `prophet`, `statsmodels`, `shap`

For production: add Celery + `ml-worker` container for actual model training with persistence.
