Connect your workplace

Set up credentials on your server, then verify the connection in Interface. Your employee records and account permissions stay under your control.

Ashby

  1. Create an API key with candidatesRead permission.
  2. Set the server variable INTERFACE_CONNECTOR_ASHBY to that key and restart.
  3. In Connectors, add an ashby connection using that variable name. Test it, then sync pages until complete.

Imports candidate names and emails. Candidates stay separate from employees. Start refresh to update existing records.

Google Workspace directory

  1. Install the optional integrations package: python -m pip install -e '.[integrations]'.
  2. Enable Google's Admin SDK and create a service account with domain-wide delegation. Authorize only the admin.directory.user.readonly scope.
  3. Set INTERFACE_CONNECTOR_WORKSPACE to a JSON object containing delegated_subject (your directory administrator email) and service_account (the complete Google credentials object).
  4. Restart and add a google_workspace connection using that variable name. Test and sync pages.

Imports names, emails, Google user IDs and suspended status. It does not create accounts or change HR records.

Google and Okta sign-in

  1. Install the integrations package above. Create an OAuth/OIDC web application in Google or Okta.
  2. Set INTERFACE_PUBLIC_URL to your Interface HTTPS origin. Configure INTERFACE_SSO_GOOGLE_CLIENT_ID and INTERFACE_SSO_GOOGLE_CLIENT_SECRET, or the corresponding INTERFACE_SSO_OKTA_* variables plus INTERFACE_SSO_OKTA_ISSUER.
  3. Register the callback at your origin plus /api/v1/auth/sso/google/callback or /api/v1/auth/sso/okta/callback. Restart Interface.
  4. Create the person's Interface account. Leave the password empty for SSO-only access.
  5. Under Connectors, link that account to the provider's subject identifier. For Google, use the Workspace user ID; for Okta, ask your identity administrator for the subject configured for your application. Do not assume it is an email.
  6. Sign out and choose Continue with Google or Okta.

Interface roles remain explicit. Unlinking an identity or deactivating its Interface account revokes local sessions. Google/Okta logout does not automatically end an existing Interface session.
